### 1.2 Werewolf ChatArena (xuyuzhuang11/Werewolf)

**设计特点：双层扮演 + 角色描述分离**

#### 系统提示词结构
```python
# agent.py 中的核心逻辑
role_prompt = player_role_desc.split('\n')[0]  # 第一行作为角色描述
message = Message(agent_name="Moderator", content=role_prompt, turn=-1, visible_to=player.name)

# global_prompt 是全局规则，注入到所有消息前
global_prompt = global_prompt.split('\n')
for prompt in global_prompt:
    message = Message(agent_name="Moderator", content=prompt, turn=-1, visible_to="all")
```

**核心理念：**
- Layer 1: AI 扮演一个有性格/背景/说话习惯的"虚拟玩家"
- Layer 2: 这个虚拟玩家在游戏里扮演具体角色（预言家/狼人等）

## 二、对比分析

### 2.1 设计范式对比

| 维度 | wolf_bot | Werewolf ChatArena | werewolf-ai-party-game | 本项目 |
|------|----------|-------------------|------------------------|--------|
| **提示词格式** | YAML 模板 | Python 字符串 | TypeScript 模板字符串 | Python f-string |
| **信息隔离** | 通过 extra_data 注入 | 通过 role_desc 隔离 | 通过 %placeholders% 分层 | 通过 visible_info_for() 函数 |
| **思考过程** | 强制输出 thinking 字段 | 不强制 | 不强制 | 强制输出思考过程 |
| **结构化输出** | JSON 格式，required_fields 验证 | 自然语言 | JSON Schema 验证 | 半结构化（文字+标记） |
| **角色差异化** | 通过策略文件加载 | 双层扮演 | 分层系统提示词 | ROLE_SPEECH_PROMPTS 字典 |
| **跨天记忆** | 通过 history 对象 | 无 | 每日总结 prompt | public_history() 函数 |
| **缓存优化** | 无 | 无 | CACHE_TIER_MARKER 分层 | 无 |

### 2.2 优势分析

#### wolf_bot 的优势
1. **JSON 结构化输出**：强制输出 thinking + speak/vote/kill 等字段，便于后端解析
2. **required_fields 验证**：LLM 响应缺少字段时自动重试，提高稳定性
3. **YAML 外部化**：提示词与代码分离，便于维护和迭代
4. **策略文件分离**：wolf_strategy、villager_strategy、god_strategy 分开管理

#### Werewolf ChatArena 的优势
1. **双层扮演机制**：Layer 1 (性格) + Layer 2 (游戏角色)，让 AI 更像真人
2. **简洁的设计**：不强制 JSON 输出，保持自然对话流
3. **可组合性**：global_prompt 和 role_desc 分离，易于扩展

#### werewolf-ai-party-game 的优势
1. **缓存分层设计**：CACHE_TIER_MARKER 将共享规则与个性化内容分离，大幅降低 token 成本
2. **强制结构化思考**：投票阶段要求先分析再投票，减少冲动决策
3. **每日总结机制**：BOT_DAY_SUMMARY_PROMPT 让 AI 主动维护记忆，避免跨天信息丢失
4. **严格的输出验证**：JSON Schema + Zod 验证，失败重试机制
5. **反模式预防**：明确列出 "ABSOLUTELY FORBIDDEN" 行为，防止 AI 犯低级错误
6. **投票位置感知**：告诉 AI 自己是第几个投票的，影响策略（早期投票更自由，晚期投票信息更多）

### 2.3 当前项目的优势与不足

#### 优势
1. **中文本土化**：完整的中文化提示词，适合国内用户
2. **角色差异化**：每个角色有独立的话术模式和失误预防
3. **信息隔离**：visible_info_for() 函数严格隔离不同角色的可见信息
4. **公开历史记录**：public_history() 提取 full_record 中的公开事件
5. **强制思考输出**：build_vote_prompt() 要求输出 "思考：<推理过程>"

#### 不足
1. **无结构化验证**：依赖 LLM 自觉输出，没有 required_fields 机制
2. **跨天记忆不完整**：虽然修复了 Bug 2（speech_round 分支），但没有主动的记忆维护机制
3. **无缓存优化**：每次请求都重复发送完整系统提示词
4. **投票无位置感知**：不告知 AI 投票顺序，可能影响策略
5. **无反模式预防**：缺少明确的 "禁止行为" 列表
6. **发言 prompt 较简单**：只有角色目标，缺少具体的话术引导示例

## 三、优化建议

### 3.1 短期优化（立即实施）

#### 建议 1：添加结构化输出验证
参考 wolf_bot 的 required_fields 机制，在 build_vote_prompt() 和 build_speech_system_prompt() 中要求 JSON 输出：

```python
# 修改 build_vote_prompt() 的输出格式要求
vote_requirement = """现在进行投票。请按以下步骤思考：

【分析步骤】
1. 逐一分析每个存活玩家的发言逻辑
2. 识别可疑点：发言矛盾、攻击性过强、回避问题、逻辑不清
3. 结合历史事件（死亡/放逐情况）
4. 综合判断谁最可疑

【输出格式】（必须输出合法 JSON）
{
    "思考": "<你的推理过程，200字以内>",
    "投票": <玩家编号，只写一个数字>
}

如果解析失败，重试 1 次（最多 2 次）。"""
```

#### 建议 2：添加反模式预防
在每个角色的 ROLE_SPEECH_PROMPTS 中添加 "禁止行为" 列表：

```python
"狼人": """...
【绝对禁止的行为】
- 说出"我是狼人"、暴露狼人同伴信息

- 对同伴投错票
- 发言过于攻击性或情绪化

- 过度辩护或解释
- 突然改变立场
- 无依据地指控其他玩家
```

### 3.2 中期优化（需要重构）

#### 建议 4：引入每日总结机制
参考 werewolf-ai-party-game 的 BOT_DAY_SUMMARY_PROMPT，在游戏结束或每天结束时让 AI 生成总结：

```python
def build_daily_summary_prompt(game, player) -> str:
    """构造每日总结 prompt，让 AI 主动维护记忆"""
    return f"""你是 {player.player_id} 号玩家，角色是 {player.role}。

【任务】总结今天的游戏事件，更新你的个人记忆。

【需要包含的内容】
1. 今天的关键事件（死亡、投票、发言）
2. 你对其他玩家的信任度评估
3. 你的怀疑目标及原因
4. 明天的策略计划

【输出格式】
请以第一人称写一段日记（200-300字）。
"""
```

#### 建议 5：缓存分层设计
将系统提示词分为两层：
- **共享层**：游戏规则、胜利条件（所有玩家相同）
- **个性化层**：角色信息、可见信息、历史事件

使用 CACHE_TIER_MARKER 分隔，让 LLM API 的 prompt caching 功能生效。

#### 建议 6：双层扮演机制
参考 Werewolf ChatArena 的 Layer 1 + Layer 2 设计：

```python
def build_role_system_prompt(game, player) -> str:
    """双层扮演：Layer 1 性格 + Layer 2 角色"""
    # Layer 1: 性格预设

    # Layer 2: 角色信息

    return f"""你是一个 {personality} 的人。

{role_info}
"""
```
