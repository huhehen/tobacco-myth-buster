# 狼人杀上下文传递问题分析报告

> 分析文件：`backend/ai/prompts.py`、`backend/game/state_machine.py`、`backend/game/director.py`、`backend/ai/speaker.py`
> 分析日期：2025-07

---

## 一、问题总览

共发现 **3 类 Bug**，均导致 AI 玩家在发言/投票时获取的上下文信息不完整或不一致：

| # | 问题 | 严重程度 | 涉及文件 |
|---|------|---------|---------|
| 1 | 跨天发言记忆丢失 | 🔴 高 | `state_machine.py`, `prompts.py` |
| 2 | `public_history()` 忽略 `speech_round` 记录 | 🔴 高 | `prompts.py` |
| 3 | 投票 prompt 中发言乱序 | 🟡 中 | `speaker.py` |

---

## 二、逐题分析

### Bug 1：跨天发言记忆丢失

**现象**：第 N 天夜晚过后，进入第 N+1 天白天的 AI 玩家，无法得知前 N-1 天其他玩家说过什么。

**根因**：`state_machine.py` 的 `_enter_night()` 方法将 `speeches_of_day` 清零（第 94 行）：

```python
# state_machine.py:91-94
def _enter_night(self):
    self.day += 1
    self.phase = "夜晚"
    self.dead_tonight = []
    self.guard_target = 0
    self.night_wolf_target = 0
    self.speeches_of_day = []  # ← 清零！前一天的发言被丢弃
```

虽然 `enter_voting()` 会在投票前把当前天发言写入 `full_record`（第 124-128 行）：

```python
# state_machine.py:123-128
def enter_voting(self):
    self.phase = "投票"
    if self.speeches_of_day:
        self.full_record.append({
            "type": "speech_round",
            "day": self.day,
            "speeches": list(self.speeches_of_day),
        })
```

但 `public_history()` **根本不看 `speech_round` 类型**，只处理 `death` 和 `execution`（见 Bug 2）。

**影响路径**：
1. `_run_day_speeches()` 在第 N 天发言时，`prior_speeches` 只包含第 N 天本轮已发言的玩家内容（`director.py:376`）
2. 第 N+1 天开始时，`speeches_of_day` 已被清空
3. AI 玩家看不到任何历史发言，只能靠 `public_history()` 里的死亡/放逐事件推断

**正确行为**：`speeches_of_day` 是临时工作列表，在 `_enter_night()` 时清零是合理的；关键是 `public_history()` 必须从 `full_record` 中读取并呈现历史发言。

---

### Bug 2：`public_history()` 忽略 `speech_round` 记录

**现象**：`full_record` 里明明保存了每一天的完整发言（`speech_round` 类型），但 `public_history()` 函数对这些记录视而不见。

**根因**：`prompts.py` 第 71-82 行，`public_history()` 的遍历逻辑只处理三种类型，且**缺少 `speech_round` 分支**：

```python
# prompts.py:71-82
for rec in game.full_record:
    d = f"第{rec['day']}天"
    t = rec['type']
    if t == 'death' and rec.get('died'):
        events.append(f"{d}天亮 {('、'.join(str(x) + '号' for x in rec['died']))} 死亡")
    elif t == 'execution':
        events.append(f"{d}白天 {rec.get('executed')}号玩家被投票放逐")
    elif t == 'vote_round':
        v = rec.get('votes') or []
        lines = [f"    {x['voter']}号投给了{('0号(弃权)' if not x['target'] else str(x['target']) + '号')}"
                 for x in v]
        events.append(f"{d}白天投票结果：\\n" + "\\n".join(lines))
    # ← 没有 elif t == 'speech_round': 分支！
```

**后果**：即使 `speech_round` 被正确写入 `full_record`，AI 玩家的 prompt 里也永远看不到历史发言内容。

**安全注意**：`speech_round` 里的发言是公开信息（任何存活玩家都能看到），将其加入 `public_history()` **不违反信息隔离**。但需注意不可混入私密的夜间决策思考（`night_thinking`）。

---

### Bug 3：投票 prompt 中发言乱序

**现象**：投票决策时，AI 收到的本轮发言列表被 `random.shuffle()` 打乱（`speaker.py:136-137`），导致 AI 无法按照发言顺序建立连贯推理链。

**根因**：`speaker.py` 第 135-137 行：

```python
# speaker.py:135-137
speeches = list(game.speeches_of_day)
random.shuffle(speeches)  # ← 注释说'避免位置偏差'，但实际破坏语义顺序
prompt = build_vote_prompt(game, player, speeches)
```

**设计意图 vs 实际效果**：
- 开发者注释称'顺序已打乱'是为了避免'位置偏差'（例如第一个人发言后的人更容易被投）
- 但乱序使 AI 无法区分'谁先说了什么'、'谁回应了谁'，这对于狼人杀的逻辑推理极为不利
- 另外，由于 Bug 1 和 Bug 2，`speeches_of_day` 此时已经是**仅当前天**的发言，乱序之后更难理解

---

## 三、full_record 中 speech_round 的 day 值分析

**`day` 值是否正确？** ✅ **正确**

时序追踪（以第 1 天为例）：
1. 游戏开始：`game.day = 0`（`state_machine.py:66`）
2. `start()` → `_enter_night()`：`day` 从 0 变为 **1**，`speeches_of_day = []`
3. 夜晚行动（狼人杀人等）
4. `resolve_night()` → 结算死亡
5. `enter_day()`：进入白天发言阶段，`day` 仍为 1
6. 白天发言：`speeches_of_day` 被填充
7. `enter_voting()`：写入 `full_record`，`day=1` ✅
8. 投票结算
9. `_run_voting()` 末尾调用 `_enter_night()`：`day` 从 1 变为 **2**，`speeches_of_day = []`

`speech_round` 的 `day` 字段始终等于**当天白天**的序号，逻辑正确。

## 四、各时刻应保存/清除的信息

| 时刻 | 应保存 | 应清除 |
|------|--------|--------|
| `_enter_night()` 开始 | — | `dead_tonight`、`guard_target`、`night_wolf_target`、`speeches_of_day` |
| `enter_day()` | `decision_thinking` → `full_record[night_thinking]` | `decision_thinking` |
| 白天发言完毕 | — | — |
| `enter_voting()` | `speeches_of_day` → `full_record[speech_round]` | — |
| 投票完毕 | 投票结果 → `full_record[execution/vote_round]` | `vote_results`、`vote_thinking` |
| 进入夜晚（`_enter_night()`） | 上一天的 `speech_round` 已持久化到 `full_record` | `speeches_of_day`（仅当前天的'临时'列表） |

**关键设计点**：
- `speeches_of_day` 是**临时工作列表**，仅在单个白天内有效，进入夜晚前需清零（这是正确的）
- **历史发言**必须通过 `full_record[speech_round]` 持久保存，并通过 `public_history()` 暴露给 AI

## 五、修复方案

### 修复 1：在 `public_history()` 中加入 `speech_round` 分支

**文件**：`backend/ai/prompts.py`，`public_history()` 函数

**修改**：在 `elif t == 'vote_round'` 分支之后，添加 `speech_round` 处理：

```python
# prompts.py:public_history() 中，在 vote_round 分支之后添加：
        elif t == "speech_round":
            for sp in rec.get("speeches", []):
                events.append(f"{d}白天 {sp['player_id']}号玩家发言：{sp['text']}")
```

> 注意：这里只输出 `player_id` 和 `text`，不暴露任何私密信息（角色、查验结果等均在 `visible_info_for()` 中单独处理）。

### 修复 2：在投票 prompt 中不使用 `random.shuffle`

**文件**：`backend/ai/speaker.py`，`_decide_target()` 方法

**修改**：删除 `random.shuffle(speeches)` 一行：

```python
# speaker.py:136 附近
speeches = list(game.speeches_of_day)
# random.shuffle(speeches)   # ← 删除这行，保持发言顺序
prompt = build_vote_prompt(game, player, speeches)
```

同时更新 `build_vote_prompt()` 中的提示文字，删除'顺序已打乱'的说法：

```python
# prompts.py:build_vote_prompt() 中：
# """以下是本轮大家的发言记录（顺序已打乱）："""
# → 改为：
# """以下是本轮大家的发言记录："""
```

### 修复 3（可选，增强）：`public_history()` 增加发言条数限制

为避免超长 prompt 导致 LLM 性能下降，建议对历史发言做截断：

```python
# prompts.py:public_history() 函数末尾 return 之前：
if len(events) > 20:
    events = events[-20:]  # 只保留最近 20 条事件
```
