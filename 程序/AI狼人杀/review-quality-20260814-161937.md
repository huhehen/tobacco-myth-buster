## 🔴 高严重度

### H1. index.html 残留损坏模板（死代码 + 无效 Alpine 表达式）
`frontend/index.html:867-869`，投票历史条目内残留半删除的"投票思考"div：

```html
<div x-show=""""
     style="..."
     x-text="'思考：' + """></div>
```

- `x-show=""""` 与 `x-text="'思考：' + """` 是**残缺的 Alpine 表达式**（引号错位，`x-text` 表达式 `'思考：' + ` 不完整），每次渲染都会求值报错。
- 该功能删除后前端状态 `_lastVoteThinking`（app.js:82）与 `handleMsg` 中 `msg.vote_thinking` 分支（app.js:476-478）一并成为死代码——**后端 `vote_result` 从不发送 `vote_thinking` 字段**（director.py:488-495 无此字段）。
- 处置：删除 867-869 三行 + app.js:82、476-478 的残留。

### H2. prompts.py 换行符被批量转义成字面 `\n`（与备份对比为回归）
`backend/ai/prompts.py:225, 250, 258, 309, 318, 355, 359, 412` 等多处使用 `"\\n"`，运行时是**字面反斜杠+n 两个字符**而非换行。同文件 triple-quoted 字符串（如 speech_requirement，321-327 行）又是真实换行——同一 prompt 内混用两种换行表示。
对比 `backups/backup-2026-08-13T14-59-02-767Z/backend/ai/prompts.py:82-83`：旧版是真实 `"\n"`，属批量替换引入的回归。LLM 收到的 prompt 里是 `\n` 文本而不是换行，影响格式约束（如"最后一行单独输出编号"）。
处置：全文件统一为真实 `"\n"`。

### H3. 投票统计逻辑双份实现（重复代码，单一事实源被打破）
- `backend/game/judge.py:81-96` `tally_votes()` 已有完整"计票+平票判定"。
- `backend/game/director.py:473-485` 又用 `from collections import Counter`（**函数内 import**）重新计票做 `vote_counts`/`vote_breakdown`。
- 且 `director.py:494` 把 `vote_counts` 的 key 转成 str（`{str(k): v}`），与同消息其他 int key 字段不一致；前端**从未消费** `vote_counts`（grep 无引用），是死载荷字段。
- 处置：复用 judge 的计票逻辑或提取公共 helper，删除未使用的 `vote_counts` 字段。
